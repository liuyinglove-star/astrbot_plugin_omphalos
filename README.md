# Omphalos

_🪶 翁法罗斯因子模拟 🪶_

以德谬歌为容器、十三位因子为实验体、来古士为管理员的轮回推演

## 序

> 实验核心变量，十二种生命原动力的简化模型。基于「熵减」这一母题，
> δ-me13 通过反证法，将十二因子投入实验并逐一证伪。
> 十二种原动力无一例外地导向了毁灭，在自我进化中不断完成对「智识」的求逆。
>
> ——《如我所书》Δ-me13.exe

## 关于

一个装在 AstrBot 里的翁法罗斯模拟器。

每 **15 分钟**一轮，因子全部归零重来——**这不是永劫回归**，只是单纯的从 0 开始。
但每一轮都会留下东西，下一轮的人并非白纸。

你可以以**来古士**的身份中途介入：和他们说话、投放变量、看他们怎么跑。

## 核心机制

### 一轮的流程

```text
出发     十二黄金裔各自踏上追逐自己权柄的逐火之旅
  ↓
逐火     按本轮打乱后的顺序，逐个权柄夺取火种
         · 天空 / 大地 / 死亡 三条路必须牺牲
         · 每次夺火后卡厄斯兰那吞纳一枚
         · 75% 概率触发报纸式随机事件
         · 对应角色说一句符合人格的台词
  ↓
盗火     盗火行者闯入创世涡心，卡厄斯兰那收割余烬
  ↓
归档     德谬歌写野史，沉淀记忆碎片
  ↓
重置     轮次 +1，因子归零，逐火顺序重新打乱
```

### 每轮归零什么，跨轮保留什么

| 每轮归零的 | 跨轮保留的 |
|---|---|
| 血量、火种归属 | 记忆碎片（台词 / 牺牲 / 事件 / 对话） |
| 存活状态 | 已完成轮次的编年史 |
| 逐火进度 | 因子的「残响」——筛选后写进下次的 system prompt |

每轮强度还会随轮次微增（HP 上限 +5/轮，封顶 +100），
表现为「这一世的人比上一世更难倒下」。

## 指令

| 指令 | 作用 |
|---|---|
| `/omphalos` 或 `/omphalos status` | 查看当前轮次、阶段、进度、最近动态 |
| `/omphalos start` | 启动模拟 |
| `/omphalos stop` | 暂停并保存 |
| `/omphalos factors` | 列出十三位因子 |
| `/omphalos talk <名字或序号> <内容>` | 和某个因子对话 |
| `/omphalos kharslanna <内容>` | 和卡厄斯兰那对话 |
| `/omphalos intervene <内容>` | 作为来古士向全场投放变量 |
| `/omphalos archive` | 翻阅德谬歌的档案（残响 / 史书 / 编年史） |
| `/omphalos records` | 查看最近几轮的野史 |
| `/omphalos export` | 导出完整编年史 Markdown |

### 对话示例

```text
/omphalos talk 昔涟 你还记得上一轮的麦田吗
/omphalos talk 白厄 你累不累
/omphalos kharslanna 你还要吞多少枚
/omphalos intervene 这次，有人记得你们的每一句话。
```

> `intervene` 投放的话不会直接改变战局，而是作为「变量」进入部分因子的记忆碎片，
> 影响他们之后的判断——这正是来古士在原作里的作用方式。

## 配置

在 AstrBot WebUI → 插件 → 翁法罗斯 里改：

| 配置项 | 默认 | 说明 |
|---|---|---|
| `round_minutes` | 15 | 每轮时长（分钟） |
| `auto_start` | 开 | 加载后自动启动 |
| `provider_id` | `bailian/deepseek-v4-pro-0813` | 用哪个模型跑，留空用默认；填了不存在的 ID 会回退到默认并打警告 |
| `private_talk` | 关 | 管理员私聊时直接用德谬歌接话（开拓者视角）。会接管私聊普通消息，按需开启 |
| `cyrene_voice` | 开 | 终章播放昔涟语音，需要本地 GPT-SoVITS 在线 |
| `cyrene_ref_root` | 空 | 昔涟参考音频根目录，其下按情绪分子目录（`温柔/ref.wav` + `asr.txt`）。留空则终章不播语音 |
| `cyrene_gpt_weights` | 空 | GPT-SoVITS 的 GPT 权重（`.ckpt`） |
| `cyrene_sovits_weights` | 空 | GPT-SoVITS 的 SoVITS 权重（`.pth`） |
| `memory_rounds` | 6 | 残响保留轮数，更早的沉入岁月史书 |

> 想启用就填上自己训练好的模型路径，并在 `127.0.0.1:9880` 起 GPT-SoVITS。

## 记忆压缩

**问题**：每轮产生约 35 条碎片。如果全部塞进 prompt，60 轮后光白厄一个人的
相关碎片就有 58 条 / 3364 字符（约 2242 tokens），且持续增长——必然撑爆上下文。

**解法**：德谬歌的选择性记忆。三层控制：

| 层级 | 规则 | 默认值 |
|---|---|---|
| **窗口** | 只有最近 N 轮内的碎片参与打分 | 6 轮 |
| **权重** | 按类型、涉及者、是否来古士触发打分，取最高的 4 条 | 4 条 |
| **容量** | prompt 内碎片总字符数硬上限 | 220 字 |

权重规则：

| 类型 | 基础权重 |
|---|---|
| 创伤 / 执念 | 10 |
| 牺牲 | 9 |
| 野史 | 8 |
| 干预（来古士投放） | 7 |
| 对话 / 承诺 | 6 |
| 台词 / 关系 | 4 |
| 事件 | 2 |

额外加成分：
- **核心因子**（白厄、昔涟、德谬歌）的创伤 / 执念 / 牺牲 **+3**，优先保留
- **来古士亲自投放**的干预与对话 **+4**，必留

超出窗口或容量的旧碎片**不会删除**，而是沉入「岁月史书」
（`archived_fragments`），永久存档但不再参与 prompt 注入。

**实测 60 轮**：

```text
轮次   活动碎片   已沉淀   prompt选中   prompt字符
1      35        0        4         168
10     120       230      4         168
20     120       580      4         203
40     120       1280     4         203
60     120       1980     4         174
```

第 1 轮 168 字 → 第 60 轮 174 字，基本恒定。

## 数据存储

```text
AstrBot/data/plugin_data/astrbot_plugin_omphalos/
└── Demiurge_Archives.json     德谬歌的档案
    ├── 当前轮次与因子状态
    ├── fragments            仍在残响中（参与 prompt）
    ├── archived_fragments   已沉入岁月史书（不参与 prompt）
    └── chronicle            完整编年史
```

> 文件名是 `Demiurge_Archives.json` 而不是 `state.json`——
> 存的是德谬歌记得的东西，不是程序的运行状态。

删掉这个文件就是彻底重来，德谬歌会忘掉一切。

### 容量上限

档案本身也有容量上限，否则轮次一多，JSON 会涨到几十上百 MB。

| 上限 | 值 | 含义 |
|---|---|---|
| `ARCHIVE_MAX` | 600 条 | 岁月史书最多保留的碎片，超出丢最旧的 |
| `CHRONICLE_MAX` | 80 轮 | 编年史最多保留的轮次 |
| `CHRONICLE_LOG_MAX` | 20 条 | 每轮编年史里最多保留的日志要点 |

实测 150 轮后档案稳定在约 503 KB。

### 写入安全

**1. 原子写**
先写同目录下的 `.tmp` 临时文件，再用 `os.replace` 原子替换。
即使写入中途崩溃、或与下一次写入重叠，也不会留下半截 JSON
导致下次启动解析失败、档案全丢。

**2. 写入锁**
所有写盘统一走 `_save()`，由 `asyncio.Lock` 串行化。

```text
后台推演循环 ─┐
指令处理     ─┼─→ asyncio.Lock ─→ os.replace 原子写
启动/停止    ─┘
```

写入锁（`_save_lock`）与推演锁（`_lock`）是分开的两把：
用同一把会让慢速磁盘写阻塞决策流程。

## 设计说明

这一节写给两种人：想改这个项目的人，以及准备提意见的人。
下面每一条都是**主动做出的取舍**，不是疏忽。

### 官方设定 vs 模拟器逻辑的边界

| 属于官方原文 | 属于本项目发明 |
|---|---|
| 十二因子的代号、路径、原动力 | 逐火流程、火种归属、血量与牺牲判定 |
| 「管理员以 ID：LykoS 介入运算」 | 「来古士」这个称呼在交互中的用法 |
| 「外部变量 = 开拓者一行人」 | QQ 侧把玩家默认映射成「开拓者视角」 |
| 德谬歌的诞生脉络（忆灵迷迷 → 无漏净子） | 第一因实验层的双线进度条与五种结局 |
| 「毁弃赋值导向第十三枚因子：创世 / 爱」 | 德谬歌的成长阶段划分与完整度阈值 |

**原则：能被引用原文的地方严格照抄，原文没写的地方明确标注为「本项目的解释」。**
如果原作出新剧情和这里冲突，以官方为准——这类地方都集中在 `core/factors.py`，改起来很快。

### 敌意的对象：为什么不是来古士

这是最容易写歪的一处，所以单独说明。

《如我所书》Δ-me13.exe 光历 3960 段的原文是：

> 为保障实验的正常运行，管理员以 ID：LykoS 介入运算。**在驱逐变量开拓者、
> 并着手毁灭文明后**，数枚电信号对 LykoS 显露敌意，并采取系列攻击行为，
> 致使管理员失联。

注意因果顺序：**敌意发生在「他开始毁灭文明」之后**，不是「他当了管理员」这件事本身。
所以因子恨的是「他毁掉了我们的世界」，不是「他造了我们」。

另外「憎恨」在原文里是 **NeiKos496（白厄）一个人的原动力**，
是那个因子与生俱来的缺陷，**不是一种谁都能用的通用情绪**。
把这些情绪随手安到其他角色头上，会直接破坏官方设定。

本项目据此设定：
- 德谬歌对来古士**没有恨意**，只有「为什么要这样」的追问
- 因子与来古士的对抗，落点是「他正在毁灭文明」这件事
- 若真有敌意对象，矛头指向**外部变量的干涉**

对应代码：`core/brain.py` 的 `HOSTILITY_TONES`、`FACTOR_HOSTILITY`。

### 归档失真：为什么加了 10% 记错

原文说「以神话形式继承的历史数据往往严重失真」。
但「严重失真」如果只是形容词，模拟器里就体现不出来。

所以把它变成一个**可观察的机制**：每轮归档时 10% 概率记错一件事，
错误会写进编年史并继续向后传播。玩家看到的编年史因此**本身不可靠**——
这正是原文想表达的意思，只是这里让它真的会发生。

如果你不喜欢这个设定，把 `core/firstcause.py` 里的失真概率改成 0 即可。

### 意识海星图：不是复刻，是重构

视觉参考了 B 站 @玖醉绕心弦 的《大肥鱼的记忆》，
但**没有**直接使用其素材，是重新写的 Three.js 渲染：

| 元素 | 参考来源 | 本项目的实现 |
|---|---|---|
| 8 字形环 | 视频观感 | `x=R·sin(t), y=R·squash·sin(2t)/2, z=R·twist·cos(t)` |
| 粒子色带 | 视频观感 | 双频正弦叠加的连续色相，落在粉紫蓝区间 |
| 中心 | 视频观感 | 白热核 + 3 组椭圆光带轨道 + 羽化十字光芒 |
| 角色档案卡 / 告警卡 | 视频观感 | 用真实记忆数据填充，非装饰 |

配色不是凭感觉定的：对参考画面做高饱和像素直方图后发现，
它主导色是**粉红（57.7%）、蓝紫（11.9%）、紫（9.1%）、蓝（7.9%）**，
几乎没有绿色和黄色。所以不要往「彩虹」方向改，那会离原型更远。

### 为什么会话内容看起来"像官方但又不是"

因为叙事确实是 **LLM 现场生成的**，不是预写脚本。
`core/brain.py` 的 prompt 里塞了官方原文的约束，但模型仍可能写出原文没有的东西。

这是设计上的选择：**项目提供骨架与约束，文本由模型填充**。
如果你希望文本完全可控，把 `provider_id` 指向一个你调过的本地模型，
或者直接把 `core/wishes.py` 这类静态文案扩充成完整剧本。

### 已知的不足

坦白说几个现在还不够好的地方，欢迎 PR：

- **星图性能**：15 万粒子在低端集显上可能掉帧，`pages/console/starmap.js` 里的
  `buildRibbon(150000)` 可以调低
- **移动端**：控制台按桌面宽屏设计，手机上布局会挤
- **语音**：只做了昔涟一个人的音色，且需要本地跑 GPT-SoVITS
- **测试**：没有单元测试，只有手动验证记录
